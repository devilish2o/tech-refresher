# Subject rotation

Use this as a guide, not a rigid timetable. Prefer the next unfinished prerequisite or the topic most useful to current work.

| Session | Main focus | Practical emphasis |
|---|---|---|
| 1 | Linux / troubleshooting | inspect processes, services and logs |
| 2 | Python | automate a repeatable operational task |
| 3 | Jenkins / CI/CD | build, test and archive an artifact |
| 4 | Networking / security | trace a connection and explain TLS |
| 5 | Terraform | plan and review an isolated change |
| 6 | Docker | build and inspect a hardened image |
| 7 | Windows / PowerShell | collect diagnostics and automate a task |
| 8 | Kubernetes | deploy and troubleshoot a local workload |
| 9 | Control-M | model dependencies and recovery |
| 10 | Axway SecureTransport | design and diagnose an MFT flow |
| 11 | Java build / WAR | package and promote one immutable artifact |
| 12 | MATLAB / review | refresh a skill and consolidate gaps |

Repeat the cycle at a higher level of difficulty. Insert Git, observability, incident response and architecture reviews where they reinforce a module.

## Evening deep dives

Use Tuesday and Thursday at 18:00 for a 45–90 minute continuation of a complex lab. A deep dive should extend the current daily topic rather than introduce an unrelated subject. If there is no unfinished lab, use the time for a scenario-based troubleshooting exercise or interview walkthrough.
